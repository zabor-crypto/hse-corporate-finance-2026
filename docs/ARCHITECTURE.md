# ADR-001 — Модульная локальная платформа

Дата решения: 2026-11-06. Задание CFLOS-T3-MVP-001. Архитектор и ведущий инженер: основной агент; финансовый исследователь, автор содержания и независимые reviewers работали раздельно.

## Решение

Новый отдельный локальный Git-репозиторий `hse-corporate-finance-2026`; предполагаемое удалённое имя — `zabor-crypto/hse-corporate-finance-2026`. Удалённый репозиторий, PR, Pages и Sites не созданы. Рабочая ветка `codex/cflos-t3-mvp`; main содержит только пустой baseline `512a890`. Разработка выполнена в отдельном sibling worktree, без изменения владельческих репозиториев.

React + TypeScript + Vite: статическая сборка, без API и сервера учебных результатов. KaTeX формирует визуальную математику и MathML. Внешняя загрузка Google Fonts необязательна; при недоступности используются локальные системные шрифты. Полной офлайн-установки/PWA в MVP нет.

- `src/content`: типизированные учебные подразделы, формулы, вопросы, карта семинара; стабильные ID и версии.
- `src/engine/finance`: чистые расчёты, явные предпосылки, ошибки входных данных и несовместимости периодов.
- `src/engine/grading`: числа с допусками, десятичная запятая, единицы, exact-set single/multi, вес этапов.
- `src/views`: обзор, урок, практика, контрольная, справочник, карта и прогресс.
- `src/components`: общие блоки, числовые поля, разбор, пошаговые примеры и лаборатория NWC.
- `src/storage`: schemaVersion=1, локальные черновики по режиму/ID/версии, неизменяемая история попыток и снимок условий задания в каждой записи.
- `tests/unit`: детерминированные проверки финансов, проверки ответов, хранения и целостности контента.
- `evidence`: фактически полученные receipts, числовые расчёты независимого reviewer, JSON unit report и скриншоты. Здесь нет исходных преподавательских PDF.

Маршрутизация hash-based позволяет открывать статическую сборку на вложенном пути без серверных rewrite. Компоненты разделены по представлениям; контент не встраивается в мегабайтный HTML. Лаборатория NWC вызывает тот же чистый финансовый движок, который покрыт тестами.

## Прогресс и обновления

`AnswerRecord` хранит режим, ID и версию задания, дату, исходный ответ, результаты этапов, балл, коды ошибок и снимок задачи. Новая версия задачи не получает автоматически старый зачёт. История старых версий доступна в экспорте и журнале. Локальная отметка урока — факт самоотметки прочтения, а не доказательство освоения.

Неизвестная схема/повреждённые данные не перезаписываются при загрузке. Импорт валидирует вложенную структуру, конфликтующие ID не подменяются. Результаты сливаются, а локальные черновики имеют приоритет; импортируемые альтернативы сохраняются в архиве. Выбор последней попытки основан на времени в UTC, независимо от порядка импорта и часового пояса. Ошибки quota/readback видны пользователю; остаётся экспорт сессионного состояния. Сброс требует отдельной явной кнопки и сохраняет результаты и архив прежних черновиков.

Контрольная хранит состав и версии заданий. Активная сессия переживает reload; несовместимый состав после обновления останавливает продолжение, не удаляя старые данные. Подсказки и разбор появляются после финальной отправки. Учебный фронтенд содержит ключи в bundle: это средство самопроверки, не защищённая аттестационная система.

## Рассмотренные альтернативы и референсы

Оба репозитория прочитаны через GitHub connector без записей. Лицензия в метаданных обоих отсутствовала; код и тексты не переносились.

В дереве `index.html` 964514 bytes, отдельный банк 1068624 bytes. Автономный собранный HTML подходит для небольшого переносимого тренажёра; для долгого учебного курса выбрана компонентная структура. Маркерная оценка открытого текста в новый продукт не перенесена.
2. [bacrf-finance-trainer, a93a917b](https://github.com/astsaryov-beep/bacrf-finance-trainer/tree/a93a917bcd7b20b7e2ca28568b5591d7791eed85). Полезные идеи: маршрут с предпосылками, различение прочтения и проверенного ответа, переход вопрос → теория → сохранённый черновик, версии вопросов и самооценка рассуждения. Тексты и реализация не копировались.

Сервер/аккаунты отложены: текущие объективные задания не требуют персональных данных или внешних вызовов. Бэкенд имеет смысл после постановки синхронизации, ролей преподавателя и проверки свободных объяснений; сейчас он увеличил бы стоимость и риски без нужной учебной функции.

## Границы решения

Не реализованы синхронизация устройств, авторизация, серверный backup, PWA, семантическая оценка открытого ответа, полный накопительный экзамен. Автоматическая семантическая оценка по ключевым словам намеренно отсутствует. Публикация и лицензия содержания остаются отдельным решением владельца.
